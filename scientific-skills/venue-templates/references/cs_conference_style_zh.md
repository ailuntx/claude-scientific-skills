# CS会议写作风格指南

适用于ACL、EMNLP、NAACL（自然语言处理）、CHI、CSCW（人机交互）、SIGKDD、WWW、SIGIR（数据挖掘/信息检索）等主要计算机科学会议的综合性写作指南。

**最后更新**：2024年

---

## 概述

计算机科学会议涵盖多个子领域，各自具有独特的写作文化。本指南涵盖自然语言处理、人机交互以及数据挖掘/信息检索领域的会议，每个领域都有特定的期望和评审标准。

---

# 第一部分：自然语言处理会议（ACL, EMNLP, NAACL）

## NLP写作理念

> "在标准基准测试中取得强有力的实证结果，并辅以深刻分析。"

自然语言处理论文需平衡实证严谨性与语言学洞察力。人工评估与自动指标同等重要。

## 受众与行文风格

### 目标读者
- 自然语言处理研究者与计算语言学家
- 熟悉Transformer架构与标准基准测试
- 要求结果可复现且包含错误分析

### 风格特征
| 特征 | 描述 |
|---------------|-------------|
| **任务导向** | 清晰定义问题 |
| **基准导向** | 强调标准数据集 |
| **深度分析** | 错误分析、定性案例 |
| **可复现性** | 完整实现细节 |

## 摘要（NLP风格）

### 结构
- **任务/问题**（1句）
- **现有工作局限**（1句）
- **你的方法**（1-2句）
- **基准测试结果**（2句）
- **分析发现**（可选，1句）

### 摘要范例

```
指代消解对于具有远距离或模糊先行词的代词仍具挑战性。现有神经方法因上下文建模不足难以处理此类复杂情况。我们提出LongContext-Coref——一种检索增强的指代消解模型，可动态检索文档历史中的相关上下文。在OntoNotes 5.0基准测试中，LongContext-Coref达到83.4 F1值，较先前最优结果提升1.2分。在具有挑战性的WinoBias数据集上，我们在保持准确率的同时将性别偏见降低34%。定性分析表明，本模型成功解决了需要世界知识的代词消解问题，这正是现有方法的已知缺陷。
```

## NLP论文结构

```
├── 引言
│   ├── 任务背景
│   ├── 现有工作局限
│   ├── 研究贡献
│   └── 贡献要点
├── 相关工作
├── 方法
│   ├── 问题定义
│   ├── 模型架构
│   └── 训练流程
├── 实验
│   ├── 数据集（含统计信息）
│   ├── 基线模型
│   ├── 主要结果
│   ├── 分析
│   │   ├── 错误分析
│   │   ├── 消融实验
│   │   └── 定性案例
│   └── 人工评估（如适用）
├── 讨论/局限性
└── 结论
```

## NLP特定要求

### 数据集
- 使用**标准基准**：GLUE、SQuAD、CoNLL、OntoNotes
- 报告**数据集统计**：训练集/验证集/测试集规模
- **数据预处理**：完整记录所有步骤

### 评估指标
- **任务适配指标**：F1、BLEU、ROUGE、准确率
- **统计显著性**：配对自助法、p值
- **多次运行**：报告随机种子下的均值±标准差

### 人工评估
生成任务中日益重要的环节：
- **标注员信息**：数量、资质、一致性
- **评估流程**：标注指南、界面设计、报酬
- **标注员一致性**：Cohen's κ或Krippendorff's α

### 人工评估表示例

```
表3：人工评估结果（100个样本，3位标注员）
─────────────────────────────────────────────────────────────
方法         | 流畅性 | 连贯性 | 事实性 | 综合评分
─────────────────────────────────────────────────────────────
基线模型     |   3.8   |    3.2    |    3.5     |   3.5
GPT-3.5      |   4.2   |    4.0    |    3.7     |   4.0
本方法       |   4.4   |    4.3    |    4.1     |   4.3
─────────────────────────────────────────────────────────────
标注员间一致性κ=0.72。评分范围：1-5（分值越高越好）。
```

## ACL特别说明

- **ARR（滚动评审）**：ACL系列会议共享评审系统
- **负责任NLP清单**：伦理、局限性、风险声明
- **长文（8页）与短文（4页）**：不同评审标准
- **Findings论文**：次级录用通道

# 第二部分：人机交互会议（CHI, CSCW, UIST）

## HCI写作理念

> "以人为本的技术——先理解用户需求，再设计与评估。"

人机交互论文本质是**以用户为中心**。仅技术新颖性不足，必须论证对用户的实际价值。

## 受众与行文风格

### 目标读者
- 人机交互研究者与实践者
- 用户体验设计师与产品开发者
- 跨学科背景（计算机、心理学、设计、社会科学）

### 风格特征
| 特征 | 描述 |
|---------------|-------------|
| **用户中心** | 聚焦人而非技术 |
| **设计驱动** | 基于设计思维 |
| **实证支撑** | 用户研究提供证据 |
| **反思深度** | 考量广泛影响 |

## HCI摘要

### 聚焦用户与影响

```
视频通话已成为远程协作的重要工具，但现有界面难以支持面对面工作特有的环境感知能力。通过对24名远程工作者的形成性访谈，我们识别出三大挑战：难以判断同事状态、缺乏环境存在感提示、沟通中断焦虑。我们设计了AmbientOffice——通过环境可视化传递成员存在感的周边显示系统。在为期两周的部署研究中（3个分布式团队的18名参与者），AmbientOffice使自发协作增加40%，显著降低孤独感(p<0.01)。参与者赞赏系统的非侵入特性，反馈与远程同事的连接感增强。我们讨论了环境感知系统的设计启示及远程工作中可见性与隐私的平衡问题。
```

## HCI论文结构

### 设计研究/系统类论文

```
├── 引言
│   ├── 人类视角的问题描述
│   ├── 技术解决方案价值
│   └── 贡献概述
├── 相关工作
│   ├── 领域背景
│   ├── 现有系统
│   └── 理论框架
├── 形成性研究（常见）
│   ├── 访谈/观察
│   └── 设计需求
├── 系统设计
│   ├── 设计原理
│   ├── 实现方案
│   └── 界面演示
├── 评估
│   ├── 研究设计
│   ├── 参与者
│   ├── 流程
│   ├── 发现（量化+质性）
│   └── 局限性
├── 讨论
│   ├── 设计启示
│   ├── 普适性
│   └── 未来工作
└── 结论
```

### 质性/访谈研究

```
├── 引言
├── 相关工作
├── 方法
│   ├── 参与者
│   ├── 流程
│   ├── 数据收集
│   └── 分析方法（主题分析、扎根理论等）
├── 发现
│   ├── 主题1（含引述）
│   ├── 主题2（含引述）
│   └── 主题3（含引述）
├── 讨论
│   ├── 设计启示
│   ├── 研究启示
│   └── 局限性
└── 结论
```

## HCI特定要求

### 参与者报告
- **人口统计**：年龄、性别、相关经验
- **招募方式**：渠道与流程
- **报酬**：金额与形式
- **伦理审批**：伦理委员会声明

### 研究发现引述
使用直接引述支撑结论：
```
参与者重视显示器的环境感知特性。如P7所述："就像开了扇通往同事办公室的窗。无需刻意查看，但我知道他们在那里。"这种被动感知降低了发起沟通的心理门槛。
```

### 设计启示章节
将发现转化为可操作指南：
```
**启示1：在不要求专注的前提下支持环境感知**
环境显示器应在视野边缘可见但无需主动监控。设计者应考虑平静技术原则。

**启示2：平衡可见性与隐私保护**
用户希望共享状态但担忧监控。系统应提供细粒度控制并确保可见性双向透明。
```

## CHI特别说明

- **贡献类型**：实证、系统、方法、理论
- **ACM格式**：采用`sigchi`选项的`acmart`文档类
- **可访问性**：需提供替代文本与包容性语言
- **贡献声明**：要求按作者列明贡献

# 第三部分：数据挖掘与信息检索（SIGKDD, WWW, SIGIR）

## 数据挖掘写作理念

> "面向现实数据的可扩展方法，具备经证实的实际影响。"

数据挖掘论文强调**可扩展性**、**实际应用性**与**严谨的实验方法**。

## 受众与行文风格

### 目标读者
- 数据科学家与机器学习工程师
- 工业界研究者
- 应用型机器学习从业者

### 风格特征
| 特征 | 描述 |
|---------------|-------------|
| **可扩展** | 处理大规模数据 |
| **实用性** | 现实场景应用 |
| **可复现** | 共享数据与代码 |
| **工业导向** | 重视工业数据集 |

## KDD摘要

### 强调规模与应用

```
电商欺诈检测需实时处理数百万交易，同时适应不断演变的攻击模式。我们提出FraudShield——面向实时欺诈检测的图神经网络框架，可扩展至十亿边规模的交易图。与需要全图访问的现有方法不同，FraudShield采用增量更新策略，单次交易推理成本为O(1)。在来自头部电商平台的23亿交易专有数据集上，FraudShield在80%召回率下达到94.2%准确率，超越生产基线12%。该系统已在[公司名]部署，每秒处理5万笔交易，预估年防欺诈损失达4亿美元。我们公开了匿名化基准数据集与代码。
```

## KDD论文结构

```
├── 引言
│   ├── 问题与影响
│   ├── 技术挑战
│   ├── 解决方案
│   └── 研究贡献
├── 相关工作
├── 预备知识
│   ├── 问题定义
│   └── 符号说明
├── 方法
│   ├── 框架概述
│   ├── 技术组件
│   └── 复杂度分析
├── 实验
│   ├── 数据集（含规模统计）
│   ├── 基线模型
│   ├── 主要结果
│   ├── 可扩展性实验
│   ├── 消融实验
│   └── 案例研究/部署
└── 结论
```

## KDD特定要求

### 可扩展性
- **数据集规模**：报告节点数、边数、样本量
- **运行时间分析**：实际耗时对比
- **复杂度**：声明时空复杂度
- **扩展实验**：展示不同数据规模下的性能

### 工业部署
- **案例研究**：实际部署案例
- **A/B测试**：在线评估结果（如适用）
- **生产指标**：业务影响（如可公开）

# 第四部分：跨领域通用要素

## 写作质量

### 清晰性
- **每句表达单一观点**
- **术语先定义后使用**
- **保持符号一致性**

### 精确性
- **精确数值**："23.4%"而非"约20%"
- **明确主张**：除非必要避免模糊表述
- **具体对比**：明确基线名称

## 贡献要点

各领域通用格式：
```
我们的贡献包括：
• 揭示[问题/洞察]
• 提出[方法名称]，其创新点为[核心创新]
• 在[基准]上实现[结果]
• 在[URL]公开[代码/数据]
```

## 可复现性标准

所有领域日益要求：
- **代码可获取**：GitHub链接（双盲评审时匿名）
- **数据可获取**：公开数据集或发布计划
- **完整超参数**：详述训练配置
- **随机种子**：提供可复现的种子值

## 伦理与社会影响

### NLP（ACL/EMNLP）
- **局限性章节**：必需
- **负责任NLP清单**：伦理考量
- **偏见分析**：涉及人类决策的模型

### HCI（CHI）
- **伦理审批**：涉及人类受试者必需
- **知情同意**：描述流程
- **隐私考量**：数据处理方式

### KDD/WWW
- **社会影响**：考量潜在滥用
- **隐私保护**：敏感数据处理
- **公平性分析**：适用场景
