# 不同出版平台的审稿人期望

了解不同出版平台的审稿人关注点对成功投稿至关重要。本指南涵盖评估标准、常见拒稿原因及应对审稿人质疑的策略。

**最后更新**：2024年

---

## 概述

不同出版平台的审稿人关注重点各异。理解这些重点可帮助您：
1. 恰当定位研究成果
2. 预判潜在批评
3. 准备有效反驳
4. 选择投稿目标

---

## 高影响力期刊（Nature, Science, Cell）

### 审稿人关注点

| 优先级 | 权重 | 说明 |
|----------|--------|-------------|
| **广泛意义** | 关键 | 超越细分领域的影响力 |
| **创新性** | 关键 | 首创成果或重大突破 |
| **技术严谨性** | 高 | 可靠方法学，合理对照 |
| **表述清晰度** | 高 | 非专业人士可理解 |
| **完整性** | 中等 | 全面但不冗长 |

### 审稿流程

1. **编辑初筛**：多数稿件未经外审即拒稿（Nature：约92%）
2. **专家评审**：送外审时由2-4位专家评审
3. **跨学科审稿人**：常包含非本领域专家
4. **快速决策**：首次决定通常需2-4周

### 常见拒稿原因

**编辑阶段**：
- 成果受众面过窄
- 相对前人工作进步有限
- 研究过于专业化
- 不符合期刊当前选题方向

**评审阶段**：
- 数据无法支撑结论
- 缺少关键对照实验
- 未排除其他解释可能
- 统计学缺陷
- 未充分引用前人工作
- 表述晦涩难懂

### 应对Nature/Science审稿人策略

**论文中**：
- 首段即阐明研究意义
- 解释成果的广泛价值
- 所有核心结论均设对照
- 使用简洁易懂的语言
- 配备概念示意图

**反驳信中**：
- 回应所有质疑（含次要问题）
- 按要求补充新数据
- 诚恳接受有效批评
- 被质疑时重申研究意义

### 审稿质疑与回应范例

**审稿人**："该工作对普通读者的意义不明确"

**回应**："我们已修改引言以阐明广泛意义。如第一段所述，本发现对[X]领域具有启示，因为[Y]。同时新增了关于成果如何深化[Z]认知的讨论（第8页15-28行）"

## 医学期刊（NEJM, Lancet, JAMA）

### 审稿人关注点

| 优先级 | 权重 | 说明 |
|----------|--------|-------------|
| **临床相关性** | 关键 | 能否改变临床实践？ |
| **方法学严谨性** | 关键 | 符合CONSORT/STROBE规范 |
| **患者结局** | 关键 | 关注患者核心指标 |
| **统计有效性** | 高 | 合理分析，统计效能充足 |
| **普适性** | 高 | 适用于更广泛人群 |

### 审稿流程

1. **统计评审**：常设专职统计审稿人
2. **临床专家评审**：细分领域专家
3. **方法学评审**：聚焦研究设计
4. **多轮修改**：常需多次返修

### 常见拒稿原因

**严重问题**：
- 研究统计效能不足
- 对照组设置不当
- 未处理混杂因素
- 选择性报告结果
- 缺失安全性数据
- 结论超出证据范围

**中等问题**：
- 普适性不明确
- 缺少亚组分析
- CONSORT/STROBE报告不全
- 统计方法描述不清

### 审稿质疑与回应范例

**审稿人**："本研究对主要结局的统计效能不足。200名受试者且事件发生率5%时，无法检测临床显著差异"

**回应**："感谢指正。我们的效能计算（方法部分第5页）基于对照组5%事件率及50%相对降幅（至2.5%）。虽观察事件率（4.8%）接近预期，但承认置信区间较宽（HR 0.65, 95% CI 0.38-1.12）。已将此列为局限性（讨论部分第12页）。需强调的是，效应方向与幅度与大型XYZ试验（n=5000）一致，建议在更大规模研究中验证"

## Cell Press系列期刊

### 审稿人关注点

| 优先级 | 权重 | 说明 |
|----------|--------|-------------|
| **机制解析** | 关键 | 作用原理阐释 |
| **研究深度** | 关键 | 多方法验证，系统全面 |
| **生物学意义** | 高 | 领域内重要性 |
| **技术严谨性** | 高 | 量化分析，统计验证，可重复 |
| **创新性** | 中高 | 新发现而非单纯验证 |

### 审稿流程

1. **深度评审**：通常≥3位审稿人
2. **多轮修改**：常需多次返修
3. **重大修订**：常要求补充关键实验
4. **逐图评估**：详细审查每张图表

### 审稿人期望

- **多方法交叉验证**：同一结论不同证明方式
- **体内验证**：细胞生物学结论需动物实验
- **挽救实验**：基因敲除/敲低研究必备
- **量化分析**：非仅展示代表性图像
- **完整图表**：包含所有条件与对照

### 审稿质疑与回应范例

**审稿人**："作者通过siRNA敲低证明蛋白X参与Y过程，但仅用单一RNAi试剂，无法排除脱靶效应，需补充证据"

**回应**："我们认同需进一步验证。修改稿中新增：(1)两种独立siRNA均产生相同表型（新图S3A-B）；(2)CRISPR-Cas9敲除细胞重现表型（新图2D-E）；(3)表达siRNA抗性蛋白X可挽救表型（新图2F-G）。这些互补方法有力支持蛋白X参与Y过程的结论"

## 机器学习会议（NeurIPS, ICML, ICLR）

### 审稿人关注点

| 优先级 | 权重 | 说明 |
|----------|--------|-------------|
| **创新性** | 关键 | 新方法/新见解/新视角 |
| **技术可靠性** | 关键 | 正确实现，公平对比 |
| **重要性** | 高 | 推动领域发展 |
| **实验严谨性** | 高 | 强基线，充分消融 |
| **可复现性** | 中高 | 他人能否复现？ |
| **表述清晰度** | 中等 | 行文流畅，结构合理 |

### 审稿流程

1. **领域主席分配**：按主题分组
2. **3-4位审稿人**：领域专家
3. **作者反驳**：回应机会
4. **审稿人讨论**：反驳后集体评议
5. **AC建议**：元评审

### 评分维度

NeurIPS/ICML典型评分：

| 维度 | 分值范围 | 评估内容 |
|-----------|-------------|------------------|
| **可靠性** | 1-4 | 技术正确性 |
| **贡献度** | 1-4 | 结果重要性 |
| **呈现质量** | 1-4 | 清晰度与组织性 |
| **综合评分** | 1-10 | 整体评估 |
| **审稿置信度** | 1-5 | 审稿人专业度 |

### 常见拒稿原因

**严重问题**：
- 基线薄弱或对比不公平
- 缺失消融实验
- 结果未显著超越SOTA
- 方法或分析存在技术错误
- 无证据支撑的过度宣称

**中等问题**：
- 相对前人工作创新有限
- 评估范围狭窄（数据集/任务少）
- 可复现细节缺失
- 表述混乱
- 分析或见解不足

### ML审稿人警惕信号

❌ "与2018年方法对比"（基线过时）
❌ "方法提升0.5%"（边际改进）
❌ "仅用单数据集评估"（泛化性存疑）
❌ "实现细节见附录"（核心信息缺失）
❌ "消融实验留待未来"（评估不完整）

### 审稿质疑与回应范例

**审稿人**："方法仅与Transformer和Performer对比，应纳入FlashAttention等近期工作"

**回应**："感谢建议。新增与FlashAttention (Dao et al., 2022)、Longformer (Beltagy et al., 2020)及BigBird (Zaheer et al., 2020)的对比。如表2所示，本方法全面超越基线：FlashAttention（低3.2%）、Longformer（低5.1%）、BigBird（低4.8%）。新增第4.3节分析本方法在>16K词长序列中的优势"

## 人机交互会议（CHI, CSCW）

### 审稿人关注点

| 优先级 | 权重 | 说明 |
|----------|--------|-------------|
| **HCI领域贡献** | 关键 | 新设计/新见解/新方法 |
| **以用户为中心** | 高 | 聚焦人类需求 |
| **合理评估** | 高 | 与宣称贡献匹配 |
| **设计依据** | 中高 | 设计决策的合理性 |
| **实践启示** | 中等 | 指导后续工作 |

### 贡献类型

CHI明确划分贡献类型：

| 类型 | 审稿人期望 |
|------|----------------------|
| **实证研究** | 严谨用户研究，明确结论 |
| **系统工具** | 新颖系统/工具，使用评估 |
| **方法论** | 新研究方法，有效性验证 |
| **理论研究** | 概念框架，学术贡献 |
| **综述** | 全面系统的领域覆盖 |

### 常见拒稿原因

**严重问题**：
- 宣称贡献与评估不匹配
- 样本量不足支撑结论
- 缺失伦理审查（无IRB）
- 技术导向缺乏用户洞察
- 对HCI社区贡献有限

**中等问题**：
- 设计依据薄弱
- 普适性有限
- 未充分关联HCI领域工作
- 实践启示不明确

### 审稿质疑与回应范例

**审稿人**："评估仅含12人短期实验室研究，未验证系统在真实场景的长期表现"

**回应**："我们承认此局限（新增7.2节讨论）。补充了8名原受试者参与的2周部署研究（新增6.3节）。纵向数据显示持续参与度（日均使用4.2次），并揭示使用模式的演变规律。但认同更大规模长期部署能增强生态效度"

## NLP会议（ACL, EMNLP）

### 审稿人关注点

| 优先级 | 权重 | 说明 |
|----------|--------|-------------|
| **任务性能** | 高 | 达到SOTA或具竞争力 |
| **分析深度** | 高 | 错误分析，机制洞察 |
| **方法学** | 高 | 可靠方法，公平对比 |
| **可复现性** | 高 | 提供完整细节 |
| **创新性** | 中高 | 新方法或新见解 |

### ACL滚动评审（ARR）

自2022年起ACL采用共享评审系统：
- 评审意见跨会议通用
- 行动编辑负责稿件
- 评审完成后选定具体会议

### 负责任NLP清单

审稿人核查：
- 局限性章节（必需）
- 风险与伦理考量
- 计算/碳足迹说明
- 偏见分析（如适用）
- 数据文档完整性

### 审稿质疑与回应范例

**审稿人**："论文缺失失败案例分析：方法何时失效？为何失效？"

**回应**："新增第5.4节错误分析。人工检查100例错误并归为三类：(1)复杂指代链（42%）；(2)隐式指代（31%）；(3)领域知识依赖（27%）。图4展示典型案例。分析表明方法在隐式指代上存在不足，这将成为未来研究方向"

## 数据挖掘会议（KDD, WWW）

### 审稿人关注点

| 优先级 | 权重 | 说明 |
|----------|--------|-------------|
| **可扩展性** | 高 | 处理大规模数据能力 |
| **实践价值** | 高 | 现实场景适用性 |
| **实验严谨性** | 高 | 全面评估 |
| **技术创新性** | 中高 | 新方法或新应用 |
| **可复现性** | 中等 | 代码/数据可获取性 |

### KDD审稿人关注亮点

- 百万级样本的大规模实验
- 工业部署或A/B测试
- 效率对比（运行时/内存）
- 真实数据集与基准测试并存
- 复杂度分析（时空维度）

### 审稿质疑与回应范例

**审稿人**："实验限于小数据集（<10万样本），方法在工业级数据上的扩展性如何？"

**回应**："新增两大数据集测试：(1) ogbn-papers100M（1.11亿节点，16亿边）；(2)[公司]提供的电商图谱（5亿节点，40亿边）。新表4显示方法近线性扩展，在ogbn-papers上42分钟完成（基线内存溢出）。新增第5.5节详细可扩展性分析"

## 通用反驳策略

### 推荐做法

✅ **回应所有质疑**：含次要问题
✅ **提供证据**：新实验/数据/文献
✅ **具体说明**：标注修改章节/行号/图表
✅ **承认有效批评**：展现理解深度
✅ **简洁表述**：审稿人需阅读大量反驳
✅ **保持专业**：即使面对不公评审
✅ **优先处理关键问题**：先解决核心质疑

### 避免做法

❌ **防御姿态**：应接受合理批评
❌ **无证据争论**：需数据支撑观点
❌ **忽略质疑**：即使不认同也需回应
❌ **模糊表述**：明确说明具体修改
❌ **攻击审稿人**：保持专业风范
❌ **承诺未来工作**：尽可能当下完成

### 反驳信模板

```
感谢审稿人的建设性意见。主要回应如下：

**R1/R2共同关注：[多位审稿人共性问题]**

[具体回应措施及修改位置标注]

**R1-1：[具体问题]**

[证据支撑的回应]

**R2-3：[具体问题]**

[证据支撑的回应]

同时完成以下改进：
• [改进项1]
• [改进项2]
```

## 投稿前自检清单

投稿前以审稿人视角自查：

### 通用项
- [ ] 结论是否有数据支撑？
- [ ] 基线方法是否恰当且最新？
- [ ] 贡献陈述是否清晰？
- [ ] 是否说明局限性？
- [ ] 可复现信息是否完整？

### 高影响力期刊
- [ ] 非专业人士能否理解意义？
- [ ] 图表是否清晰易懂？
- [ ] 对照设置是否充分？

### 医学期刊
- [ ] 是否符合CONSORT/STROBE？
- [ ] 是否报告绝对数值？
- [ ] 临床相关性是否明确？

### 机器学习会议
- [ ] 消融实验是否全面？
- [ ] 对比是否公平？
- [ ] 可复现信息是否完整？

### 人机交互会议
- [ ] 用户中心视角是否明确？
- [ ] 评估方法是否匹配宣称贡献？
- [ ] 设计启示是否具可操作性？
