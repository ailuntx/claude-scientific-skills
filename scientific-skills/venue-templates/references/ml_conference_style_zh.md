# 机器学习会议写作风格指南

适用于NeurIPS、ICML、ICLR、CVPR、ECCV、ICCV等主流机器学习与计算机视觉会议的综合写作指南。

**最后更新**：2024年

---

## 概述

机器学习会议优先关注**创新性**、**严谨的实证评估**和**可复现性**。论文评审标准包括：贡献清晰、基线方法强、消融实验全面、对局限性的诚实讨论。

### 核心理念

> "展示而非空谈——你的实验应证明主张，而非仅靠文字描述。"

**首要目标**：通过严谨实验验证的创新方法推动技术前沿发展。

---

## 受众与行文基调

### 目标读者

- 机器学习研究者与实践者
- 特定子领域专家
- 熟悉近期文献
- 要求技术深度与精确性

### 行文特征

| 特征         | 描述                 |
|--------------|----------------------|
| **技术性**   | 包含密集方法论细节   |
| **精确性**   | 术语准确，无歧义     |
| **实证性**   | 主张需实验支撑       |
| **直接性**   | 明确陈述贡献         |
| **诚实性**   | 承认局限性           |

### 语态

- **第一人称复数（"我们"）**："我们提出..." "我们的方法..."
- **主动语态**："我们引入新型架构..."
- **自信而克制**：重大主张需强有力证据支撑

## 摘要

### 风格要求

- **信息密集且数据导向**
- **150-250词**（因会议而异）
- **前置关键结果**：包含具体指标
- **连贯段落**（非结构化）

### 摘要结构

1. **问题**（1句）：解决什么问题？
2. **现有工作局限**（1句）：当前方法为何不足
3. **你的方法**（1-2句）：方法核心
4. **关键结果**（2-3句）：基准测试具体数据
5. **意义**（可选，1句）：研究价值

### 摘要范例（NeurIPS风格）

```
Transformer在序列建模中取得显著成功，但其二次计算复杂度限制了长序列应用。
我们提出FlashAttention-2——一种IO感知的精确注意力算法，在16K词元序列上
比FlashAttention提速2倍，比标准注意力最高提速9倍。核心创新是通过分块与重计算
减少内存读写，实现最优IO复杂度。在Long Range Arena基准测试中，FlashAttention-2
在保持标准注意力精度的同时支持8倍长序列训练。结合序列并行技术，我们以近线性成本
在64K词元序列上训练GPT类模型。我们发布优化CUDA内核，在A100 GPU上达到理论峰值
FLOPS的80%。代码见[匿名链接]。
```

### 摘要禁忌

❌ "我们提出解决X的新方法"（模糊，无结果）
❌ "本方法优于基线"（无具体数据）
❌ "此问题很重要"（自证性主张）

✅ 包含具体指标："准确率94.5%，提升3.2%"
✅ 注明规模："100万样本"或"16K词元序列"
✅ 提供对比："比先前SOTA快2倍"

## 引言

### 结构（2-3页）

机器学习引言需采用**带编号贡献点**的独特结构。

### 段落指南

**首段：问题动机**
- 问题重要性
- 应用场景
- 技术挑战定位

```
"大语言模型在自然语言理解与生成中展现卓越能力。然而其二次注意力复杂度
成为处理长文档、多轮对话和扩展上下文推理的根本瓶颈。当模型规模达数十亿参数、
上下文长度延至数万词元时，高效注意力机制对实际部署至关重要。"
```

**第二段：现有方法局限**
- 现有技术
- 不足原因
- 局限性技术分析

```
"先前研究通过稀疏注意力模式、线性注意力近似和低秩分解解决此问题。这些方法
虽降低理论复杂度，但常牺牲精度、需专用硬件或在深度网络中产生累积近似误差。
当计算资源允许时，精确注意力仍是首选方案。"
```

**第三段：方法概览（高层描述）**
- 核心洞见
- 方法概念原理
- 成功依据

```
"我们发现注意力主要瓶颈并非计算而是内存带宽——在现代GPU上读写庞大N×N注意力矩阵
主导运行时。我们提出FlashAttention-2，通过分块策略逐块计算注意力而不需完整矩阵，
从而消除此瓶颈。"
```

**第四段：贡献列表（关键）**

此为机器学习会议**强制且特色要求**：

```
我们的贡献如下：

• 提出FlashAttention-2——IO感知的精确注意力算法，实现最优内存复杂度O(N²d/M)，
  其中M为GPU SRAM容量。

• 理论分析表明，在典型GPU配置下本算法比FlashAttention减少2-4倍HBM访问。

• 在256至64K词元序列上，相比FlashAttention提速2倍，比标准PyTorch注意力最高提速9倍。

• 证明FlashAttention-2可在同等硬件上支持8倍长上下文训练，解锁长程建模新能力。

• 在[匿名链接]发布优化CUDA内核及PyTorch绑定。
```

### 贡献点撰写准则

| 优质贡献点              | 劣质贡献点                |
|-------------------------|---------------------------|
| 具体可量化              | 模糊主张                  |
| 自成一体                | 需读全文理解              |
| 彼此独立                | 内容重叠                  |
| 突出创新性              | 陈述明显事实              |

### 相关工作位置

- **引言中**：简要定位（1-2段）
- **独立章节**：详细对比（结尾或结论前）
- **附录**：篇幅受限时扩展讨论

## 方法

### 结构（2-3页）

```
方法
├── 问题定义
├── 方法概览/架构
├── 关键技术组件
│   ├── 组件1（含公式）
│   ├── 组件2（含公式）
│   └── 组件3（含公式）
├── 理论分析（如适用）
└── 实现细节
```

### 数学符号

- **定义所有符号**："令X∈ℝ^{N×d}表示输入序列..."
- **符号一致性**：相同符号始终指代相同含义
- **重要公式编号**：便于后续引用

### 算法伪代码

为可复现性提供清晰伪代码：

```
算法1: FlashAttention-2前向传播
─────────────────────────────────────────
输入: Q, K, V ∈ ℝ^{N×d}, 分块大小 B_r, B_c
输出: O ∈ ℝ^{N×d}

1:  将Q划分为T_r = ⌈N/B_r⌉块
2:  将K, V划分为T_c = ⌈N/B_c⌉块
3:  初始化 O = 0, ℓ = 0, m = -∞
4:  for i = 1 to T_r do
5:    从HBM加载Q_i至SRAM
6:    for j = 1 to T_c do
7:      从HBM加载K_j, V_j至SRAM
8:      计算 S_ij = Q_i K_j^T
9:      更新运行最大值与求和
10:     增量更新O_i
11:    end for
12:   将O_i写入HBM
13: end for
14: 返回 O
```

### 架构图

- **清晰可发表的矢量图**：PDF/SVG格式
- **栅格图高分辨率**：300+ dpi
- **实际印刷尺寸可读**：按栏宽测试
- **色盲友好**：除颜色外使用图案区分

## 实验

### 结构（2-3页）

```
实验
├── 实验设置
│   ├── 数据集与基准
│   ├── 基线方法
│   ├── 实现细节
│   └── 评估指标
├── 主要结果
│   └── 核心对比表/图
├── 消融研究
│   └── 组件分析
├── 深入分析
│   ├── 扩展性表现
│   ├── 定性示例
│   └── 错误分析
└── 计算效率
```

### 数据集与基准

- **采用标准基准**：确保可比性
- **报告数据集统计**：规模/划分/预处理
- **说明非标选择**：若用自定义数据需解释原因

### 基线方法

**对论文接收至关重要**。需包含：
- **近期SOTA**：非陈旧方法
- **公平对比**：相同算力/超参调优
- **消融版本**：移除关键组件的变体
- **强基线**：勿选择弱势对比方法

### 主结果表

清晰全面的表格格式：

```
表1: Long Range Arena基准测试结果（准确率%）
──────────────────────────────────────────────────────────
方法          | ListOps | 文本  | 检索    | 图像  | 路径  | 平均
──────────────────────────────────────────────────────────
Transformer     |  36.4   | 64.3  |   57.5    | 42.4  | 71.4  | 54.4
Performer       |  18.0   | 65.4  |   53.8    | 42.8  | 77.1  | 51.4
Linear Attn     |  16.1   | 65.9  |   53.1    | 42.3  | 75.3  | 50.5
FlashAttention  |  37.1   | 64.5  |   57.8    | 42.7  | 71.2  | 54.7
FlashAttn-2     |  37.4   | 64.7  |   58.2    | 42.9  | 71.8  | 55.0
──────────────────────────────────────────────────────────
```

### 消融研究（强制要求）

展示方法关键要素：

```
表2: FlashAttention-2组件消融研究
──────────────────────────────────────────────────────
变体                              | 加速比 | 内存比
──────────────────────────────────────────────────────
完整FlashAttention-2              |   2.0x  |  1.0x
  - 无序列并行                    |   1.7x  |  1.0x
  - 无重计算                      |   1.3x  |  2.4x
  - 无分块策略                    |   1.0x  |  4.0x
FlashAttention-1 (基线)           |   1.0x  |  1.0x
──────────────────────────────────────────────────────
```

### 消融研究要素

- **组件必要性**：移除导致性能下降
- **设计选择依据**：架构/超参合理性
- **失效场景**：方法何时失效
- **敏感性分析**：超参鲁棒性

## 相关工作

### 位置选择

1. **引言后**：计算机视觉论文常见
2. **结论前**：NeurIPS/ICML常见
3. **附录**：篇幅紧张时

### 写作风格

- **按主题组织**：非时间顺序
- **定位自身工作**：与每类研究的差异
- **客观描述**：勿曲解前人工作
- **近期文献**：包含2023-2024论文

### 结构范例

```
**高效注意力机制**。先前高效注意力研究分三类：稀疏模式(Beltagy等,2020；
Zaheer等,2020)、线性近似(Katharopoulos等,2020；Choromanski等,2021)和
低秩分解(Wang等,2020)。我们的工作聚焦IO高效的精确注意力而非近似方法。

**内存高效训练**。梯度检查点(Chen等,2016)和激活重计算(Korthikanti等,2022)
通过计算换内存降低开销。我们采用类似思想但应用于注意力算子内部。
```

## 局限性章节

### 重要性

NeurIPS、ICML、ICLR**日益强制要求**。诚实说明局限：
- 体现科学严谨性
- 指导未来工作
- 避免过度宣传

### 内容要素

1. **方法局限**：何时失效？
2. **实验局限**：未测试场景？
3. **范围局限**：未覆盖领域？
4. **计算局限**：资源需求？

### 局限性范例

```
**局限性**。尽管FlashAttention-2显著加速，仍存在局限：1) 实现针对NVIDIA GPU优化，
不支持AMD等硬件；2) 加速效果在中长序列显著，极短序列(<256词元)内核启动开销占主导；
3) 聚焦稠密注意力，扩展至稀疏模式是未来方向；4) 理论分析基于特定GPU内存层次参数，
未来硬件可能不适用。
```

## 可复现性

### 可复现性清单（NeurIPS/ICML）

多数机器学习会议要求包含：

- [ ] 代码可获取性
- [ ] 数据集可获取性
- [ ] 超参数说明
- [ ] 随机种子报告
- [ ] 计算需求说明
- [ ] 实验次数与方差报告
- [ ] 统计显著性检验

### 报告要素

**超参数**：
```
"采用Adam优化器(β₁=0.9, β₂=0.999, ε=1e-8)，学习率3e-4经1000步线性预热后余弦衰减。
8块A100 GPU上批大小256，训练10万步（约24小时）。"
```

**随机种子**：
```
"所有实验取3个随机种子(0,1,2)平均值，括号内标注标准差。"
```

**计算资源**：
```
"实验在8块NVIDIA A100-80GB GPU完成，总训练耗时约500 GPU小时。"
```

## 图表

### 质量要求

- **优先矢量图**：PDF/SVG格式
- **栅格图高分辨率**：300+ dpi
- **实际印刷尺寸可读**：按栏宽测试
- **色盲友好设计**：辅以图案区分

### 常用图表类型

1. **架构图**：可视化方法
2. **性能图**：学习曲线/扩展性
3. **对比表**：主结果
4. **消融图**：组件贡献
5. **定性示例**：输入输出样本

### 图注要求

独立成文的图注需说明：
- 图表内容
- 解读方式
- 核心结论

## 参考文献

### 引用格式

- **编号[1]**或**作者-年份(Smith等,2023)**
- 遵循会议特定要求
- 全文格式统一

### 引用准则

- **引用近期工作**：需含2022-2024论文
- **勿过度自引**：易引发偏见质疑
- **规范引用arxiv**：优先正式发表版本
- **覆盖相关研究**：遗漏引用损害评审

## 会议特性说明

### NeurIPS

- **正文8页**+附录/参考文献不限
- 有时需**广泛影响**章节
- **可复现性清单**强制
- OpenReview提交，公开评审

### ICML

- **正文8页**+附录/参考文献不限
- 强调**理论+实验**结合
- 鼓励可复现性声明

### ICLR

- **正文8页**（定稿可超）
- OpenReview公开评审讨论
- 作者回复期互动性强
- 强调**创新性与洞察深度**

### CVPR/ICCV/ECCV

- **正文8页含参考文献**
- 鼓励**补充视频**
- 高度重视**可视化结果**
- 基准性能至关重要

## 常见错误

1. **基线较弱**：未与近期SOTA方法比较  
2. **缺少消融实验**：未展示各组件贡献  
3. **过度宣称**：仅部分解决问题却声称"我们解决了X"  
4. **贡献表述模糊**：仅声明"提出新方法"  
5. **可复现性差**：缺失超参数/随机种子  
6. **模板错误**：使用过期的会议格式文件  
7. **违反匿名原则**：双盲评审中暴露身份  
8. **忽略局限性**：未说明失败场景  

---

## 反驳技巧  

机器学习会议设有作者回复环节。建议：  
- **优先回应关键质疑**：聚焦核心问题  
- **补充必要实验**：时间允许时完成  
- **保持简洁**：审稿人需阅读大量回复  
- **保持专业态度**：即使面对不公评审  
- **引用具体位置**：如"如原文第127行所述..."
