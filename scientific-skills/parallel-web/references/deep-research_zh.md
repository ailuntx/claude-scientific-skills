# 深度研究

研究主题：$ARGUMENTS

## 何时使用（与网络搜索对比）

仅当用户明确要求深度/详尽研究时才使用此功能。深度研究比网络搜索慢10-100倍且更昂贵。对于普通的“研究X”请求、快速查询或事实核查，请改用 **网络搜索**。

## 步骤 1：启动研究

设定研究目标以优先获取学术文献。如果用户的查询是科学或技术性的，请在参数前添加引导至学术来源的上下文——例如，不要使用 `"睡眠剥夺的影响"`，而使用 `"关于睡眠剥夺影响的同行评审研究与临床研究"`。这能引导研究代理偏向原始文献，同时不排除相关的非学术来源。

```bash
parallel-cli research run "$ARGUMENTS" --processor pro-fast --no-wait --json
```

如果这是对先前研究或丰富任务的 **后续追问**，并且你知道 `interaction_id`，可以添加上下文链：

```bash
parallel-cli research run "$ARGUMENTS" --processor lite --no-wait --json --previous-interaction-id "$INTERACTION_ID"
```

通过在多个请求间链式传递 `interaction_id`，每个后续问题都会自动拥有前几轮的全部上下文——这样你可以深入探讨某个主题，无需重复陈述已研究过的内容。对于后续追问使用 `--processor lite`，因为繁重的研究已在初始轮次完成，后续只需在此上下文基础上构建。

此命令会立即返回。**不要**省略 `--no-wait`——否则命令会阻塞数分钟并超时。

处理器选项（根据用户请求选择）：

| 处理器 | 预期延迟 | 使用场景 |
|--------|---------|----------|
| `pro-fast` | 30秒 - 5分钟 | 默认——深度与速度的良好平衡 |
| `ultra-fast` | 1 - 10分钟 | 更深入分析，更多来源（约2倍成本） |
| `ultra` | 5 - 25分钟 | 最大深度，仅在明确要求时使用（约3倍成本） |

解析JSON输出以提取 `run_id`、`interaction_id` 和监控URL。立即告知用户：
- 深度研究已启动
- 所选处理器层级的预期延迟（来自上表）
- 可跟踪进度的监控URL

告知他们可以在轮询步骤进行时后台处理，继续其他工作。

## 步骤 2：轮询结果

根据主题选择描述性文件名（例如 `ai-chip-market-2026`、`react-vs-vue-comparison`）。使用小写字母和连字符，不要空格。

```bash
parallel-cli research poll "$RUN_ID" -o "$FILENAME" --timeout 540
```

重要：
- 使用 `--timeout 540`（9分钟）以保持在工具执行限制内
- **不要**传递 `--json`——完整输出很大，会淹没上下文。`-o` 标志改为将结果写入文件。
- `-o` 标志会生成两个输出文件：
  - `$FILENAME.json` —— 元数据和依据
  - `$FILENAME.md` —— 格式化的Markdown报告
- poll 命令会在研究完成时将 **执行摘要** 打印到标准输出。将这份执行摘要分享给用户——无需打开文件即可快速了解概览。

### 如果轮询超时

更高处理器层级可能超过9分钟。如果 poll 退出未完成：
1. 告知用户研究仍在服务端运行
2. 重新运行同样的 `parallel-cli research poll` 命令以继续等待

## 回复格式

**步骤1之后：** 分享监控URL（仅用于跟踪进度——并非最终报告）。

**步骤2之后：**
1. 分享 poll 命令打印到标准输出的 **执行摘要**
2. 简要评估来源质量：引用来源中同行评审期刊、预印本或机构报告与新闻文章或博客文章的比例如何。如果学术覆盖薄弱，请向用户指出，并建议针对特定数据库进行后续搜索（例如“我可以专门在PubMed/arXiv上搜索更多关于此主题的原始来源”）。
3. 告知用户生成的两个文件路径：
   - `$FILENAME.md` —— 格式化的Markdown报告
   - `$FILENAME.json` —— 元数据和依据
4. 分享 `interaction_id` 并告知用户他们可以提出在此研究基础上构建的后续问题（例如“深入探讨X”或“将其与Y比较”）

完成后**不要**再次分享监控URL——结果在文件中，而非该链接。

询问用户是否希望阅读文件以获取更多细节。除非用户要求，否则**不要**将文件内容读入上下文。

**记住 `interaction_id`** —— 如果用户提出与此研究相关的后续问题，请在下一个研究或丰富命令中使用它作为 `--previous-interaction-id`。
