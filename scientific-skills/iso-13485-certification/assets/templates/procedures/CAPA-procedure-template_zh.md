## 1. 目的

本程序规定以下要求：  
- 通过纠正措施消除不符合项的根本原因并防止复发  
- 通过预防措施消除潜在不符合项的根本原因并防止发生  
- 对问题与风险进行系统性调查分析  
- 实施并验证有效行动  
- 持续改进质量管理体系  

本程序确保符合 ISO 13485:2016 条款 8.5.2（纠正措施）和 8.5.3（预防措施）。  

---

## 2. 范围

本程序适用于：  
- 通过任何途径识别的不符合项（内部审核、客户投诉、过程监控、产品检验等）  
- 通过风险分析、趋势分析和主动评审识别的潜在不符合项  
- 所有产品、过程及质量管理体系要素  
- [公司名称] 内所有部门及人员  

---

## 3. 定义

| 术语 | 定义 |
|------|------------|
| **CAPA** | 纠正与预防措施 |
| **纠正措施** | 为消除已发现不符合项或其他不良状况的根本原因，防止复发而采取的行动 |
| **预防措施** | 为消除潜在不符合项或其他潜在不良状况的根本原因，防止发生而采取的行动 |
| **不符合项** | 未满足要求 |
| **根本原因** | 问题发生的根本原因 |
| **根本原因分析 (RCA)** | 识别问题根本原因的系统性过程 |
| **有效性检查** | 验证已实施措施是否达到预期效果 |
| **5 Whys** | 用于探究因果关系的迭代式提问技术 |
| **鱼骨图** | 分类问题潜在原因的可视化工具（亦称石川图） |

## 4. 职责

### 4.1 质量经理  
- CAPA 系统总体责任  
- 评审所有 CAPA 的充分性  
- 批准 CAPA 关闭  
- 在管理评审中报告 CAPA 指标  
- 确保 CAPA 活动资源到位  

### 4.2 CAPA 协调员  
- 管理 CAPA 数据库/系统  
- 分配 CAPA 编号  
- 跟踪 CAPA 状态与截止日期  
- 发送超期行动提醒  
- 生成 CAPA 指标与报告  
- 维护 CAPA 记录  

### 4.3 CAPA 负责人（指定人员）  
- 主导调查与根本原因分析  
- 制定行动计划  
- 实施纠正/预防措施  
- 协调相关部门  
- 记录所有 CAPA 活动  
- 执行有效性检查  
- 完成后申请 CAPA 关闭  

### 4.4 部门经理  
- 为 CAPA 活动提供资源与支持  
- 参与管辖范围内的调查  
- 在部门内实施措施  
- 验证措施执行情况  

### 4.5 全体人员  
- 报告不符合项与改进机会  
- 按要求参与 CAPA 调查  
- 执行分配的行动  
- 支持 CAPA 有效性

## 5. 程序

### 5.1 纠正措施流程

纠正措施针对以下来源识别的不符合项启动：  

**不符合项来源：**  
- 客户投诉（依据 SOP-[编号]）  
- 内部不合格品（依据 SOP-[编号]）  
- 内部审核发现（依据 SOP-[编号]）  
- 过程监控超规格结果  
- 产品检验不合格  
- 供应商不符合项  
- 法规检查或观察项  
- 管理评审行动项  
- 风险管理输出  
- 退回或拒收产品  

**5.1.1 CAPA 启动**  

1. 发现不符合项时，发现人应：  
   - 填写 CAPA 申请单（附件 A）或在 CAPA 系统中录入信息  
   - 清晰完整描述不符合项  
   - 附支持文件（不合格报告、投诉记录、审核发现等）  
   - 提交至质量部门  

2. CAPA 协调员应：  
   - 接收 CAPA 申请  
   - 分配唯一 CAPA 编号：CAPA-[年份]-[###]  
   - 在跟踪系统中登记 CAPA  
   - 转交质量经理评审  

3. 质量经理应：  
   - 评审 CAPA 申请的完整性与清晰度  
   - 判定是否需要采取纠正措施  
   - 确定优先级（见第 5.3 节）  
   - 指定 CAPA 负责人  
   - 根据优先级设定截止日期  
   - 批准启动 CAPA 调查  

### 5.2 预防措施流程

预防措施主动启动，旨在问题发生前消除潜在风险。  

**预防措施来源：**  
- 投诉、不合格报告等数据的趋势分析  
- 风险管理活动（依据 SOP-[编号]）  
- 过程能力研究  
- 未遂事件  
- 其他组织或设备的经验教训  
- 法规或标准变更  
- 主动过程改进  
- 管理评审输出  
- 员工建议  

**5.2.1 预防措施启动**  

流程同纠正措施（第 5.1.1 节），但需：  
- 描述潜在不符合项及其可能后果  
- 提供支持预防措施必要性的数据或依据  
- 可能根据发生风险采用不同优先级  

### 5.3 CAPA 优先级划分

所有 CAPA 按以下因素划分优先级：  
- 影响严重性（安全、法规、客户影响）  
- 发生频率或可能性  
- 到达客户前的可检测性  

**优先级等级：**  

| 优先级 | 判定标准 | 完成截止期限 |
|----------|----------|-------------------------|
| **严重** | 安全问题、法规要求、重大客户影响、I 类召回风险 | [X] 天 |
| **高** | 显著质量影响、重复问题、中度客户影响、需法规报告 | [X] 天 |
| **中** | 中度影响、孤立事件、轻微客户影响 | [X] 天 |
| **低** | 轻微影响、孤立事件、无客户影响、改进机会 | [X] 天 |

优先级由质量经理会同 CAPA 负责人及相关部门经理确定。  

### 5.4 调查与根本原因分析

**5.4.1 调查计划**  

CAPA 负责人制定调查计划，包括：  
- 调查范围  
- 所需团队成员（如适用）  
- 待收集数据  
- 拟采用分析方法  
- 时间表  

**5.4.2 数据收集**  

收集相关数据：  
- 审查相关记录（批记录、检验记录、培训记录等）  
- 访谈相关人员  
- 审查历史类似事件  
- 检查实体证据（产品样品、设备等）  
- 审查适用程序与作业指导书  
- 分析可用趋势数据  

**5.4.3 根本原因分析**  

根据问题复杂度选用 RCA 工具：  

**简单问题：**  
- 5 Whys 技术  
- 因果分析  

**复杂问题：**  
- 鱼骨图（石川图）  
- 故障树分析  
- 失效模式与影响分析（FMEA）  
- 统计分析  

**RCA 要求：**  
- 深入挖掘根本原因，不止于表象  
- 区分症状与原因  
- 考虑多重影响因素  
- 反复追问"为什么"直至确定根本原因  
- 评估人为因素、程序缺陷、系统弱点  
- 记录分析过程与结果  

**5.4.4 根本原因记录**  

在 CAPA 记录中记录：  
- 调查结果摘要  
- 确定的根本原因  
- 支持数据与分析  
- 使用的 RCA 工具  
- 参与团队成员  
- 调查完成日期  

质量经理评审并批准根本原因判定。  

### 5.5 行动计划与实施

**5.5.1 行动计划制定**  

基于根本原因，CAPA 负责人制定行动计划：  

**行动必须满足：**  
- **有效性：** 针对根本原因而非症状  
- **可行性：** 符合可用资源  
- **可测量：** 包含客观成功标准  
- **及时性：** 设定目标完成日期  
- **风险适配：** 与严重性及可能性相称  

**行动计划包含：**  
- 具体行动项  
- 每项行动责任人  
- 每项行动目标完成日  
- 所需资源  
- 预期结果/成功标准  
- 有效性验证方法  

**5.5.2 行动类型**  

行动可包括：  
- 程序修订或澄清  
- 培训或再培训  
- 设备维修、更换或改造  
- 过程变更或改进  
- 设计变更（如适用）  
- 供应商纠正措施要求  
- 加强检验或监控  
- 软件更新或验证  
- 物理设施变更  
- 组织架构调整  

**5.5.3 行动批准**  
- CAPA 负责人提交行动计划至质量经理  
- 质量经理评审充分性与适当性  
- 相关部门经理评审涉及其领域的行动  
- 质量经理批准行动计划  
- 行动分配至责任人并设定截止日  

**5.5.4 实施**  
- 责任人执行分配行动  
- 记录实施过程（程序修订、培训记录等）  
- CAPA 负责人跟踪实施进展  
- CAPA 协调员发送超期行动提醒  
- 长期 CAPA 提供中期进展更新  

**5.5.5 实施记录**  

每项行动记录：  
- 实施日期  
- 实施证据（更新程序、培训记录、工单等）  
- 与计划行动的偏差及理由  
- 责任人确认  

### 5.6 有效性评审

**5.6.1 有效性检查时机**  

有效性在以下时间验证：  
- 实施后经过足够观察期  
- 最短：[X 天/周] 后  
- 过程或趋势验证延长至：[X 个月]  
- 根据优先级及问题性质确定时间  

**5.6.2 有效性验证方法**  

适用方法包括：  
- 审查过程/产品数据以确认性能改进  
- 显示改进的检验或测试结果  
- 规定时期内未复发  
- 客户反馈或投诉趋势  
- 内部审核验证  
- 过程能力分析  
- 相关指标的统计分析  
- 纠正措施区域再审核  
- 跟进检验或测试  

**5.6.3 有效性判定**  

CAPA 负责人应：  
- 按计划方法收集有效性数据  
- 分析数据判定是否达成预期效果  
- 在 CAPA 记录中记录结果  
- 建议有效性状态：  
  - **有效：** 达成预期结果且未复发  
  - **无效：** 未达成预期结果或复发  
  - **需补充数据：** 时间或数据不足无法判定  

**5.6.4 无效行动处理**  

若判定行动无效：  
- CAPA 保持开启状态  
- 执行重新调查  
- 制定替代行动  
- 循环直至有效性达成  

### 5.7 CAPA 关闭

**5.7.1 关闭标准**  

满足以下条件可关闭 CAPA：  
- 所有计划行动已实施并验证  
- 有效性检查完成且判定有效  
- 全部文件记录完整  
- 有效性观察期内未复发  

**5.7.2 关闭流程**  

1. CAPA 负责人：  
   - 确认所有关闭标准满足  
   - 完成最终 CAPA 摘要  
   - 向质量经理提交关闭申请  

2. 质量经理：  
   - 全面评审 CAPA 记录的完整性  
   - 验证有效性证据  
   - 批准关闭或要求补充信息  
   - 签署并注明 CAPA 关闭日期  

3. CAPA 协调员：  
   - 更新 CAPA 状态为"已关闭"  
   - 按保存要求归档 CAPA 记录  
   - 更新指标与报告  

**5.7.3 CAPA 延期**  

如需延长时间：  
- CAPA 负责人提交附理由的延期申请  
- 质量经理评审并批准/拒绝  
- 设定新截止日期  
- 在 CAPA 记录中记录延期
