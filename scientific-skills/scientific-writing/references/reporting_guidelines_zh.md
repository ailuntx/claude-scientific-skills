# 科学研究报告指南

## 概述

报告指南是基于证据的建议，规定了报告特定类型研究时应包含的信息。它们提供检查清单和流程图，确保报告完整、准确且透明，这对读者评估研究有效性以及其他研究人员复现工作至关重要。

EQUATOR网络（提升健康研究质量与透明度）维护着全面的报告指南库。使用适当的报告指南可提高稿件质量并增加发表接受率。

## 为何使用报告指南？

### 优势

**对作者而言：**
- 确保重要内容不被遗漏
- 提高稿件接受率
- 改善稿件组织结构
- 减少审稿人补充信息的要求

**对读者和审稿人而言：**
- 支持对研究有效性的批判性评估
- 促进系统综述和荟萃分析
- 提升对实际操作的认知

**对科学界而言：**
- 增强可复现性
- 减少研究浪费
- 提高透明度
- 支持更优质的证据整合

### 使用时机

- **研究设计阶段**：许多指南包含方案版本（如SPIRIT用于试验方案）
- **稿件撰写阶段**：使用检查清单确保覆盖所有条目
- **投稿前**：核查依从性并常随稿提交检查清单
- **多数期刊要求**：将报告指南检查清单作为投稿要件

## 按研究类型划分的主要报告指南

### CONSORT - 随机对照试验

**全称：** 试验报告统一标准

**适用场景：** 任何随机对照试验（RCT），包括预试验和可行性试验

**最新版本：** CONSORT 2010（更新版声明）

**核心要素：**
- **检查清单**：25个条目覆盖标题、摘要、引言、方法、结果、讨论
- **流程图**：展示参与者从入组、分配、随访到分析的流程

**主要检查条目：**
1. 标题标明随机试验性质
2. 结构化摘要
3. 科学背景与理论基础
4. 具体目标与假设
5. 试验设计描述（平行、交叉、析因等）
6. 参与者入选标准
7. 数据收集场所与地点
8. 详细描述可复现的干预措施
9. 明确定义主要与次要结局指标
10. 样本量确定与效能计算
11. 随机序列生成方法
12. 分配隐藏机制
13. 盲法实施
14. 统计方法
15. 参与者流程及脱落原因
16. 招募日期与随访日期
17. 基线特征表
18. 各结局指标分析结果
19. 伤害事件与不良反应
20. 试验局限性
21. 结果外推性
22. 结果解读一致性
23. 试验注册编号
24. 完整方案获取途径
25. 资金来源

**特定设计扩展版：**
- 整群随机试验CONSORT
- 非劣效性与等效性试验CONSORT
- 实效性试验CONSORT
- 交叉试验CONSORT
- N-of-1试验CONSORT
- 阶梯楔形设计CONSORT

**访问地址：** http://www.consort-statement.org/

### STROBE - 观察性研究

**全称：** 流行病学观察性研究报告规范

**适用场景：** 队列研究、病例对照研究、横断面研究

**最新版本：** STROBE 2007（广泛采用标准）

**覆盖主要研究设计：**
- **队列研究**：追踪暴露组与非暴露组随时间变化
- **病例对照研究**：比较病例组与对照组的暴露史
- **横断面研究**：同步测量暴露因素与结局指标

**主要检查条目（22项）：**
1. 标题摘要标明研究设计
2. 背景与理论基础
3. 研究目标
4. 研究设计及理论依据
5. 研究场所、地点及时间
6. 入选标准与筛选方法
7. 明确定义变量（结局、暴露、混杂因素）
8. 数据来源与测量方法
9. 偏倚控制策略
10. 样本量依据
11. 定量变量处理方法
12. 统计方法（含混杂与交互作用）
13. 敏感性分析
14. 参与者流程及未参与原因
15. 描述性数据（含随访时间）
16. 结局数据
17. 主要结果（含未校正与校正估计值）
18. 其他分析（亚组、敏感性分析）
19. 关键结果总结
20. 局限性及潜在偏倚讨论
21. 结果解读与外推性
22. 资金来源及作用

**扩展版：**
- STROBE-ME（分子流行病学）
- RECORD（常规收集健康数据）
- STROBE-RDS（受访者驱动抽样）

**访问地址：** https://www.strobe-statement.org/

### PRISMA - 系统综述与荟萃分析

**全称：** 系统综述与荟萃分析优先报告条目

**适用场景：** 含或不含荟萃分析的系统综述

**最新版本：** PRISMA 2020（重大更新）

**核心要素：**
- **检查清单**：27个条目覆盖所有章节
- **流程图**：研究筛选流程

**主要章节：**
1. **标题**：标明系统综述/荟萃分析
2. **摘要**：结构化概要
3. **引言**：理论基础与目标
4. **方法**：
   - 纳入标准
   - 信息来源（数据库、时间范围）
   - 检索策略（至少一个数据库完整策略）
   - 筛选流程
   - 数据提取流程
   - 提取数据项
   - 偏倚风险评估
   - 效应测量指标
   - 结果合成方法
   - 报告偏倚评估
   - 证据确定性评估（如GRADE）
5. **结果**：
   - 研究筛选流程图
   - 研究特征
   - 偏倚风险评估结果
   - 合成结果（如适用荟萃分析）
   - 报告偏倚
   - 证据确定性
6. **讨论**：
   - 局限性
   - 结果解读
   - 实践意义

**扩展版：**
- PRISMA摘要版
- PRISMA方案版（PRISMA-P）
- 网状荟萃分析PRISMA
- 范围综述PRISMA（PRISMA-ScR）
- 个体患者数据PRISMA
- 诊断准确性PRISMA
- 公平性系统综述PRISMA

**访问地址：** http://www.prisma-statement.org/

### PRISMA流程图

**阶段：**
1. **识别阶段**：来自数据库和注册库的记录
2. **筛选阶段**：记录经过筛选后被排除
3. **纳入阶段**：进入综述与综合的研究

**PRISMA 2020新特性：**

- 明确区分报告与独立研究

## 常见错误及避免方法

### 错误1：完全不使用指南

**影响**：遗漏关键信息，降低稿件接受率

**解决方案**：从研究规划阶段识别并采用合适指南

### 错误2：仅在稿件完成后使用指南

**影响**：可能发现关键数据未收集或记录

**解决方案**：在研究设计和数据收集阶段审阅指南

### 错误3：清单填写不完整

**影响**：未报告遗漏项目

**解决方案**：系统处理清单中的每个条目

### 错误4：使用过时指南

**影响**：缺失最新报告标准的改进内容

**解决方案**：始终在官方指南网站核查最新版本

### 错误5：研究设计匹配错误指南

**影响**：未报告设计相关的关键要素

**解决方案**：仔细选择匹配研究设计的指南

### 错误6：未按要求提交清单

**影响**：编辑部直接拒稿或延迟处理

**解决方案**：查阅期刊投稿指南并附上清单

### 错误7：笼统报告缺乏细节

**影响**：无法复现或评估研究

**解决方案**：为每个条目提供具体详细信息

## 期刊要求

### 多数期刊现要求：

1. **方法部分声明**遵守报告指南
2. **完整清单**作为补充文件上传
3. 清单标注**页码/行号**指明对应内容位置
4. **流程图**作为稿件插图

### 方法声明示例：

```
"本研究遵循《加强流行病学观察性研究报告》(STROBE)声明。完整的STROBE清单见补充文件1。"
```

### 严格要求指南的期刊：

- PLOS系列（特定研究类型需提交清单）
- BMJ（要求CONSORT、PRISMA等）
- The Lancet（要求遵守声明）
- JAMA及JAMA Network期刊（要求清单）
- Nature系列期刊（鼓励采用指南）

## 清单：使用报告指南

**研究开始前：**
- [ ] 确定适用的报告指南
- [ ] 审阅需前瞻性规划的清单条目
- [ ] 设计研究以捕获所有必要元素
- [ ] 如适用则注册研究方案

**稿件撰写阶段：**
- [ ] 下载最新版指南清单
- [ ] 系统处理每个清单条目
- [ ] 创建必备流程图
- [ ] 标注条目对应位置（页码/行号）

**投稿前：**
- [ ] 完成含页码的正式清单
- [ ] 验证所有条目已充分说明
- [ ] 方法部分包含遵守声明
- [ ] 按要求准备补充文件版清单
- [ ] 核对期刊特定要求
- [ ] 在投稿信中提及指南遵守情况

## 特定场合的报告要求

### 不同场合的报告标准

| 场合类型       | 指南使用         | 透明度要求               |
|----------------|------------------|--------------------------|
| **医学期刊**   | 强制（CONSORT、STROBE等） | 投稿时需提交清单         |
| **PLOS/BMC**   | 特定研究类型强制 | 清单作为补充材料上传     |
| **Nature/Science** | 推荐         | 强调方法完整性           |
| **ML会议**     | 无正式指南       | 需提供可复现性细节       |

### ML会议报告标准

**NeurIPS/ICML/ICLR可复现性要求：**
- **数据集**：名称、版本、获取方式、预处理
- **代码**：可用性声明（常用GitHub）
- **超参数**：完整设置（学习率、批大小等）
- **随机种子**：确保结果可复现
- **计算资源**：GPU型号、训练时长
- **统计显著性**：误差线、置信区间、多次运行
- **社会影响声明**（NeurIPS要求）：技术的社会影响

**需包含内容（通常置于附录）：**
- 完整超参数设置
- 训练细节与收敛标准
- 硬件规格
- 软件版本（如PyTorch 2.0）
- 数据集划分及预处理
- 评估指标与协议

### 执行与核查

**核查内容：**
- **医学期刊**：清单上传；方法部分声明；系统完整性
- **PLOS/BMC**：特定设计强制清单；强调可复现性
- **高影响力期刊**：方法需支持复现（通常不强制清单）
- **ML会议**：可复现性清单（NeurIPS）；代码可用性渐成标配

**常见拒稿原因：**
- 缺失必备清单（医学期刊）
- 方法细节不足无法复现
- 缺少关键信息（随机化、盲法、功效计算）
- 未按要求提供数据/代码声明

**方法声明示例：**

**期刊（STROBE）：**
```
本研究遵循STROBE报告指南。完整清单见补充文件1。
```

**ML会议（可复现性）：**
```
代码详见github.com/用户/项目。全部超参数见附录A。
训练使用4×A100 GPU（约20小时）。随机种子：{42, 123, 456}。
```
