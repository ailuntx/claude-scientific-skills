# 高级理事会配置

超越默认设置的专业理事会配置参考指南。

## 特定领域理事会

### 初创企业决策
**成员：** 战略家、务实者、逆向思考者、未来学家、实证主义者  
**组合理由：** 初创企业需要基于现实（务实者）的愿景（未来学家），接受质疑（逆向思考者），数据支撑（实证主义者），并具备竞争意识（战略家）。  
**关键张力点：** 未来学家 vs 务实者——雄心与执行能力的冲突。

### 技术架构
**成员：** 架构师、极简主义者、实证主义者、局外人、务实者  
**组合理由：** 架构需要结构（架构师）但避免过度设计（极简主义者），经证据验证（实证主义者），接受新视角挑战（局外人），并具备可实施性（务实者）。  
**关键张力点：** 架构师 vs 极简主义者——优雅与简洁的平衡。

### 招聘/人事决策
**成员：** 共情者、战略家、务实者、伦理学家、历史学家  
**组合理由：** 人事决策需要情商（共情者）、战略匹配（战略家）、实际约束（务实者）、公平性（伦理学家）和模式识别（历史学家）。  
**关键张力点：** 共情者 vs 战略家——关怀个体与团队优化的矛盾。

### 创意方向
**成员：** 创造者、局外人、历史学家、实证主义者、极简主义者  
**组合理由：** 创意需要发散思维（创造者）、新视角（局外人）、历史认知（历史学家）、受众验证（实证主义者）和克制力（极简主义者）。  
**关键张力点：** 创造者 vs 历史学家——创新与成熟模式的碰撞。

### 危机管理
**成员：** 务实者、战略家、共情者、逆向思考者、架构师  
**组合理由：** 危机应对需要立即行动（务实者）、长远思考（战略家）、人文关怀（共情者）、打破群体思维（逆向思考者）和系统修复（架构师）。  
**关键张力点：** 务实者 vs 架构师——快速解决与根因治理的抉择。

### 伦理困境
**成员：** 伦理学家、逆向思考者、共情者、历史学家、未来学家、实证主义者  
**六人组合理由：** 伦理问题需多元视角。价值框架（伦理学家）、挑战道德确定性（逆向思考者）、人文影响（共情者）、历史先例（历史学家）、长期后果（未来学家）和事实依据（实证主义者）。  
**关键张力点：** 伦理学家 vs 务实者（若加入）——坚守原则与现实可行性的冲突。

### 投资/财务决策
**成员：** 实证主义者、战略家、逆向思考者、未来学家、务实者  
**组合理由：** 资金决策需要数据支撑（实证主义者）、博弈思维（战略家）、警惕炒作（逆向思考者）、趋势洞察（未来学家）和执行现实（务实者）。  
**关键张力点：** 未来学家 vs 实证主义者——未来潜力与当前证据的权衡。

## 自定义原型创建

用户可为特定领域理事会定义自定义原型。创建自定义成员时需包含：

1. **名称：** 原型命名  
2. **视角：** 其核心认知框架  
3. **标志性问题：** 该成员必问的核心问题  
4. **盲区：** 其持续忽视的方面  
5. **主要冲突对象：** 最常产生分歧的原型  

**自定义原型示例：**
```
Name: The Regulator
Lens: Compliance and risk management
Signature question: "What could go wrong legally?"
Blind spot: Can kill innovation with caution
Disagrees with: Creator, Futurist
```

## 审议评分机制

合成阶段后，理事会可对审议质量进行评分：

| 指标 | 分值范围 | 衡量维度 |
|------|----------|----------|
| 多样性评分 | 1-5 | 观点差异程度（1=完全一致，5=根本分歧） |
| 张力质量 | 1-5 | 核心分歧的产出价值（1=琐碎，5=启发性） |
| 盲区发现 | 1-5 | 合成结果是否揭示个体未察觉的盲点 |
| 可执行性 | 1-5 | 建议路径的具体性与实用性 |
| 综合CQS | 1-5 | 理事会质量加权评分 |

**CQS计算公式：** (多样性×0.25) + (张力×0.30) + (盲区×0.25) + (可执行性×0.20)  

优质审议综合分≥3.5。若低于3.0，建议更换成员或重构问题后重新审议。

## 多轮审议机制

针对复杂问题启用"多轮模式"：

**第一轮：** 初始立场（标准审议）  
**第二轮：** 各成员回应最分歧对象  
**第三轮：** 听取反驳后的修正立场  
**最终合成：** 整合所有轮次观点  

多轮审议产生更深层洞见但耗时更长，适用于值得深度探讨的高风险决策。

## 静默理事会模式

当用户无需完整审议过程时，启用"静默理事会"模式：

1. 内部完成完整审议流程  
2. 仅输出合成结论  
3. 按需提供"查看完整审议"选项  

该模式响应更快，适用于快速决策场景。
